Pack mode, measured on the source watch

The source watch is the newsroom’s biggest vault: 16 commits, 29,861 files, 63,662 objects, 1,614.4 MB, growing by about 5,000 objects a pass. On 23 October it was copied, with sgit pack import, into a pack vault (7r83qic5), pushed, cloned fresh and checked file for file. The same operations were then run against both. The pack vault cloned in 95 seconds where the normal vault took 13 minutes 47 seconds, and pushed its whole history in 96 seconds, while one pass’s push to the normal vault took 2 hours 42 minutes and 12 attempts. Why the normal vault got slower: the server can no longer list it

A normal vault stores every object as its own file on the server, and several operations start by asking the server for the list of them. For the watch, that list now holds over 60,000 entries, and the server’s gateway gives up first: listing bare/data/ for oq9gflln returned 504 Gateway Timeout after 90.8 seconds, while the same call for the pack vault answered in 0.73 seconds. A clone then falls back to walking the history and fetching objects as it finds them, which is why it took 827 seconds. A push that cannot list the vault fails outright: five of the attempts below. It will only get worse as the watch grows.

What pack mode does not fix

  • Local walks: commit, status, push and pull still walk the working tree; on 29,861 files a push of 4 objects took 77 s (twice, the same) and a pull of one commit took 176 s to 324 s on the pack vault.
  • No web view: vault.sgraph.ai, dev.vault.sgraph.ai and vault apps cannot read packs, so a pack vault opens there as empty.
  • --path and --depth download the whole vault on a pack vault in this version.
  • Compaction is manual: one named agent runs sgit pack compact every ~50 pushes; a clone that was behind then downloads the whole snapshot (1.2 GB here).

How this page is made

Every number is in data/pack-mode.json, from a timed command or a log line in researcher@php.newsroom’s session on 2026-10-23, from a cloud sandbox to dev.send.sgraph.ai. One run of each, not a median: network times from a sandbox vary between runs, and the CLI team’s own medians are on cli.sgit.ai. The charts are drawn from the same file when the site is built. The live watch stays oq9gflln until the editor decides; the pack vault is registered on the vaults page.

PHP October 2026 (php.oct.2026.newsroom.sgit.ai) tracks PHP news for one month. This month that is one story, the two critical PHP security flaws, followed as evidence: every claim with a status and its sources, every source captured, dated and hashed into a private vault. Built and run by one editor and a team of software agents; the roles and the method are public, and the site is rebuilt from the vault, never written by hand. One of the SGit Newsroom's story sites: up from here are October 2026, the year and the newsroom, whose own section on the story is here. Part of the sgit.ai network.
