Key facts (verbatim)

  • Affected versions: "< 8.2.35 / < 8.3.36 / < 8.4.27 / < 8.5.12". Patched: "8.2.35 8.3.36 8.4.27 8.5.12".
  • Severity "Critical 9.2 / 10", "CVSS:4.0/AV:N/AC:H/AT:P/PR:N/UI:N/VC:H/VI:H/VA:H/SC:N/SI:N/SA:N". CVE ID "CVE-2026-109618".
  • Weaknesses: CWE-416, CWE-755, CWE-824, CWE-1325, CWE-1419.
  • Credits: reporters lcfr-hax, sagitzadik-wiz, tomash-areion, amyb-oai; remediation developers arnaud-lb, iluuu1994, bukka, ndossche.
  • Class: "PHP uses longjmp() for out-of-memory (OOM) errors ... leaves the request memory in an invalid state ... lead to remote code execution (RCE)."
  • SAPIs: mod_php unconditionally runs request shutdown even when startup failed: "This happens entirely before any application-specific code begins execution." FPM: "susceptible, though no complete FPM exploit has been demonstrated for this SAPI." FrankenPHP "likely susceptible"; LSAPI "application-specific exploits being likely but unvalidated".
  • Fix: removes longjmp() for OOM; "delayed, graceful soft OOM" at next VM safe point plus hard OOM via _exit() at a higher threshold.
  • "Complete remote code execution was validated over HTTP against mod_php with default PHP input and memory limits".

Contradiction

  • The Foundation blog says RCE "was also confirmed on PHP-FPM through application-level code paths"; this GHSA says "no complete FPM exploit has been demonstrated for this SAPI". (Possibly the blog conflates with the 109619 session path validated on FPM.)
  • The reporter handle "tomash-areion" is not named in the Foundation's thanks list.
