Briefing for Taylor, project or programme manager · ******Plain English # What unplanned work does this create, who do I chase, and what do I tell stakeholders? T The answer in thirty seconds Expect unplanned work this week: updating PHP on every system that uses it, restarting, and re-testing. Some teams may take systems offline for hours as a precaution. Anything still on PHP 8.1 or older has no ready-made fix and becomes a migration project. Ask each system owner for a patch date and a test plan. Read the site as Taylor → This is a platform event, not an application bug, so it lands on every team that ships anything running on PHP at once. Plan for it the way you would plan for a datacentre move: an inventory, an owner per system, a date, a test. ## What to decide or do - **Get the list.** Which systems run PHP, who owns each, and which are on the internet. Vendor products and hosting panels count. Without the list nothing else can be scheduled. - **Get a date per system.** Updating PHP means installing the fixed version, restarting, rebuilding containers and re-testing. Internet-facing systems first. - **Budget for regression testing.** The fix changes how PHP behaves when it runs short of memory: a system that used to limp along may now stop cleanly. Load tests are worth running before the release, not after. - **Plan for precautionary downtime.** Agencies advise isolating or taking offline what cannot be updated in time. Agree with stakeholders now who can make that call, how long it may last, and what users see meanwhile. - **Treat PHP 8.1 and older as a project.** There is no ready-made release for them. Moving to a supported version is a migration with its own scope and schedule. - **Expect a second round.** A report that the first fix may be incomplete is open. Keep a slot free in the next fortnight. ## Your reading path - Your briefing - Explained from scratch - If you run PHP - Impact: offline vs compromised - Timeline Choose *read as Taylor* and the bar under the menu keeps your place on every page. ### What this briefing covers - what unplanned work this creates - which systems and owners to chase - what to tell stakeholders about downtime - what changes after the fix ### What you can skip - the code - the bug classes - the detection rules ## The facts this rests on Show the 20 claims behind this briefing, each with its status and sources- confirmed two or more primary sources agree, or the fact was counted from a captured file - reported one party says so, and it has not been contradicted - disputed the sources disagree, and both readings are shown - contradicted a primary source says otherwise - unverified even the reporting outlet could not check it - p/n primary sources among the n cited;
