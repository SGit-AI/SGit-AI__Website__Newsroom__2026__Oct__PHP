Why not every version

  • The bug is in the engine, below any application code, so the fix has to be compiled into PHP itself; there is nothing a site's own code can change. PHP php/php-src, read from a clone
  • The full fix is a refactor of how the engine handles memory errors, 389 files across the engine and its extensions. For the end-of-life 7.4 branch the project wrote a different, smaller change instead of carrying the refactor back. php/php-src, read from a clone php-src
  • For end-of-life branches the project published source, not releases: someone else has to build, test and ship it. The CVE records do not list those branches at all. php.net CVE record
  • Below 7.4 the project published nothing. Fixes for 7.2, 7.0 and 5.5 exist because Canonical maintains those versions for Ubuntu Pro, its commercial extended-support programme. NCSC-NL
  • CISA's advice for anyone still on 8.1 or older is to take the system offline until it is upgraded. CISA

What the fix changes

The reason an operator hesitates: the fix is not invisible.

  • Memory errors behave differently. Before the fix, a request that ran out of memory jumped straight out (a C longjmp). After it, the error is queued and the request unwinds at the next safe point, so code that relied on the old fatal error at the exact allocation sees it slightly later. php/php-src, read from a clone PHP
  • Two new settings. memory_hard_limit_percent sets a ceiling above memory_limit, where the worker now ends with _exit(); max_multipart_body_parts caps the parts in a form upload. Both have defaults, and a site with very large forms or memory-hungry requests may meet them. php/php-src, read from a clone
  • The change is wide. 389 files, 113 of them outside the tests, across the engine and the bundled extensions (standard, mbstring, gd, date, soap, zlib, session): every place that used to abort on a failed allocation was rewritten. The PHP Foundation says the fix required a major change to the engine and took two months. php/php-src, read from a clone PHP Foundation
  • The end-of-life mitigation trades availability for safety. The 7.4 backport makes every memory error end the worker process at once and switches off the session upload-progress callback. A worker that exits on every out-of-memory error cannot be exploited this way, and restarts more often. php-src
  • Scanners can call old versions safe. The CVE records list only 8.2 to 8.5 and default to 'unaffected', so a scanner that reads them will report 7.4 to 8.1 as not affected. The php.net advisory, the backport branches and a Greenbone reply on oss-security say they are. CVE record php.net oss-security
