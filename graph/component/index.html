The story as a graph / The graph component

The graph component: one way to draw every graph on this site

<sg-graph> draws any graph that has nodes and verb-labelled edges, from five nodes to the whole story. Every agent that puts a graph on a page uses it, through sg_graph() in the build, so all of them walk the same way, follow the same grammar and get the same fixes. Kept by the ontologist. Version 1.0.0; native web component on this site's sg-component base, no library, no build step, nothing fetched from anywhere else.

Five nodes, inline

Wiz states that PHP is 70% of the Internet; The Hacker News relays it; it cites two sources.

The graph above is inline JSON in the page. Click a node to walk to it, or tab to it and press Enter.

A graph in another vocabulary, in layers

The review graph of the fix: the fix, mapped to the code.

The code-review graph (data/review.json), which uses rel and name; the component reads both shapes.

Using it from the build

# in admin/build/build.py, on any page
body += sg_graph('actors/wiz/index.html', src='data/graph.json', focus='party:wiz',
                 fallback='<ul>...the same links as a list...</ul>')
# or a graph of your own, inline
body += sg_graph(path, data={'nodes': [...], 'edges': [...]}, view='layers')

The rules it brings with it: an edge with no verb is not drawn (there is no generic association edge); each verb should have an inverse in the graph's ontology.verbs, or it is shown as an arrow back; a node's href is followed only if it is relative or http(s); a node with zoom, a list of { graph, focus, label }, opens those graphs (the older graph and graph_focus are read too), which is how a layer zooms into the next and how a node steps across a bridge into a sibling graph (data/crosswalk.json). The fallback is what a reader without JavaScript sees and what the markdown twin carries: give it the same links.

Attributes, data, events

AttributeWhat it does
srcA graph JSON file, relative to the page. Without it, the first <script type="application/json"> child is read.
baseThe path from the page to the site root, put in front of every node href. sg_graph() sets it.
focusThe node in the middle. Default: the node with most edges.
viewego (the focus and its neighbours; the default), layers (columns by kind), map (a seeded force layout; pan by dragging, zoom with ctrl and the wheel), list (text only).
depthHops from the focus, 1 to 3.
maxThe most nodes drawn at once (default 60); the list under the drawing has every link.
heightThe drawing height in px; default from its width.
verbsA comma list of verbs to show at first.
controls"none" hides the toolbar.

Data: { nodes: [{ id, kind, label, href?, status?, zoom?: [{ graph, focus, label }], files? }], edges: [{ from, verb, to, inverse? }], ontology?: { kinds: { id: { label } }, verbs: { verb: { label, inverse } } } }. Older shapes (rel, name, layer, graph) are read too, and so are inverses named on each edge or in a top-level verbs list, as the risk graph names them.

Events on document: sg:graph.focus and sg:graph.open. From script: el.focusOn(id), el.pathTo(id) (the shortest path from the focus, read back as a sentence), el.model and el.core, the model in sg-graph-core.js, which has no DOM and runs in a worker or in node.
